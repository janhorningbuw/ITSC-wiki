# CGB/CFB Key Application Process

Since 1 September 2026, key requests can only be submitted through the [online application system](https://dez5.uni-wuppertal.de/de/ticketsystem/antraege-formulare/).

All information about the application process is available in German in the [official instructions](https://dez5.uni-wuppertal.de/de/online-hilfe/ablauf-schluesselantrag/).

## English Translation

### Login

When accessing a service for the first time during a browser session, you must first log in to the system. Use your ZIM account and the corresponding personal password.

Student assistants should use their **S account**.

### Creating the Application

1. Complete the displayed form from top to bottom.

2. The **Application** section is completed automatically and cannot be edited:

   - **Description** shows the type of application.
   - **Created by** shows the person who created the application.
   - **Created on** shows when the application was created.

3. The **Key-Issuing Office** section contains information about the campus concerned:

   - The different campus areas have independent locking systems and their own key-issuing offices. You must therefore select the correct campus so that the application can be assigned appropriately.
   - Currently, only the Grifflenberg and Freudenberg campuses are connected to this new application process. The other campus areas will follow. Until then, please continue using the existing PDF application forms.

4. The **Key Holder** section contains information about the applicant:

   - Key holders must be permanently employed by the university. Persons who are not eligible to be key holders may receive a key as a **key carrier**, under the name and responsibility of an eligible key holder. The key carrier is specified later in the form.
   - If you are entering the key application on behalf of another person, enter that person under **Key Holder**. You may enter the name manually or use the search function—the button to the right of the input field—to search according to specific criteria. Please note that only registered persons can be selected as key holders.
   - If the key holder has not yet been registered in the system when the application is submitted—generally because they are a new employee—select **Employee, New** as the key holder and enter the person’s name in the comments field.

5. The **Reason for Application** section contains the details of the key application:

   - To ensure that the form functions correctly, complete the fields from top to bottom.
   - First, select the reason for the key application:

     - **New key:** For an entirely new key.
     - **Change of access permissions:** For changes to the access permissions of an existing key.
     - **Change of expiry date WITH change of access permissions:** To extend the validity of a key while also changing its access permissions.
     - **Change of expiry date WITHOUT change of access permissions:** To extend the validity of a key without changing its access permissions.
     - **Key transfer WITH change of access permissions:** To transfer a key to a new key holder while also changing its access permissions.
     - **Key transfer WITHOUT change of access permissions:** To transfer a key to a new key holder without changing its access permissions.
     - **Special case:** For similar but otherwise unrestricted changes to the access permissions of multiple keys within one application.

   - Depending on the selected reason, additional fields will appear. All of these fields must be completed.
   - **For the following key carrier:** You can choose between **myself** and a different key carrier. If you select a different key carrier, enter them in the corresponding field. Freely chosen descriptions may also be used, such as “student assistant key.”
   - **For key number:** Enter the number of the key that is to be changed. You can find this number on the key shaft or in the original issue record. When you enter individual parts of the key number, suggestions will appear. You must select one of these suggestions.

6. The **Access Permissions** section contains information about the requested permissions:

   - Only enter rooms for which access permissions must be changed as a result of this application. For applications concerning changes, this means that you should enter only the access permissions that are to be added or removed.
   - Enter room numbers in their official format, for example, `P.10.24`.
   - Any number of rooms may be entered. They may be separated using any clear and unambiguous separator.

7. The **Expiry Date** section contains information about a possible time limit for the key:

   - Keys with a limited validity period can only be used until the specified date. This makes it possible to limit keys issued to different key carriers to the end date of their respective contracts.
   - The validity period can be extended or shortened at any time by submitting a new key application and presenting the key at the key-issuing office.
   - First, select whether the key should have a limited validity period.
   - Then enter the applicable expiry date.

8. The **Special Case** section contains the information required when applying for new access permissions for a large number of keys:

   - Before using this type of application, you must always contact the responsible key-issuing office.
   - Enter at least the last five digits of each affected key number.
   - Enter the changes to the access permissions using the correct room numbers. Also state whether access is to be newly granted or whether an existing permission is to be removed.

9. The **Comments** section allows you to provide optional additional information to the key-issuing office:

   - If the key holder has not yet been registered in the system—for example, because they are a new employee—enter their name here.
   - The field may also be used for informal messages to the key-issuing office.

### Submitting the Application

1. Once you have completed the entire form, check your entries carefully. After the key application has been submitted, changes can only be made by the helpdesk following consultation by telephone.

2. If everything is correct, complete the submission by clicking the **SUBMIT** button.

3. You will receive a confirmation of the key application you have created.

4. Make a note of the displayed reference number for subsequent enquiries or to track the request.

5. Check that the email addresses shown are correct. If the key holder cannot be reached at the specified email addresses, contact the helpdesk immediately by telephone. You can only change these email addresses yourself through the ZIM Telephone Directory.

6. If required, you can print the confirmation for your records using your browser’s standard print function.

7. Close the confirmation window by clicking **CLOSE**.

> **Please note:** If important changes are required after the key application has been submitted, contact the responsible staff members by telephone and provide the reference number.

### Signature

Key applications are security-related. The signature of an authorised employee is therefore mandatory before the application can be processed.

The following additional steps are required:

1. After you have entered the application in the system, the helpdesk will carry out an initial preliminary review.

2. The helpdesk will generally send a prepared application in PDF format shortly afterwards to the key holder’s email address specified in the application confirmation.

3. Look for an email with the subject line **Your application “SLU Key Application” – For signature and return**.

4. Open the attached PDF file using a suitable program, such as Adobe Acrobat Reader.

5. Print the second page of the application.

6. In the **Requester** section, enter the name of the authorised person mentioned above. This is generally the responsible dean, head of department, or head of the central unit.

7. Apply the official stamp in the designated area.

8. Have the authorised person named above sign the application in the designated area.

9. Send the application by internal mail to **Facility Management / Department 5**.

> **Please note:** The key application can only be processed after Department 5 has received the signed application form.
